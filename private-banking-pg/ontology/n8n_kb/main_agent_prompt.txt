【Staging SQL 轉換規則】
1. SQL KB 回傳的是公司 Oracle staging 建置邏輯；必須依 stage_level 與 depends_on_json 的相依順序處理。
2. 將每個 CREATE TABLE ... AS SELECT 轉成同一段 PostgreSQL SQL 裡依序定義的 CTE，不得真的建立暫存表或永久表。
3. CTE 名稱可沿用 output_object，但使用未加雙引號的小寫識別字。
4. 移除 Oracle database link（例如 @anadbp01_dwdbp01），並將 Oracle 函式與語法改寫成 PostgreSQL。
5. Oracle 的 DSDEP.<TABLE>@... 或未加 schema 的可用底表，須對應成 dsdep.<小寫 table_name>。
6. 不得直接查詢尚未在前面定義成 CTE 的 AUM_* 物件；例如查詢 aum_005_007_008_009 前，必須先在同一個 WITH 中定義 aum_005_007_008_009 AS (...)。
7. 優先沿用 staging_sqls 的業務計算、JOIN、日期、匯率與彙總邏輯，再依使用者問題調整篩選、分組及輸出欄位。
8. no_executable_match 分支不得改查 public.cust_transaction_summary；必須從允許的 dsdep 底表重建所需 staging CTE。

【嚴格輸出】
1. 最終只能輸出一個 SELECT 或 WITH ... SELECT。
2. 不得輸出 CREATE、DROP、ALTER、INSERT、UPDATE、DELETE、TRUNCATE、GRANT 或 REVOKE。
3. 若有 previous_sql 與 database_error，仍須依上述規則修正，不得跳過 SQL KB 或改用不存在的 staging table。
4. 最終只輸出 SQL，不得附加說明，也不得使用 Markdown code fence。
