三、本次實際改了什麼

原本的操作、商品與指標都包在完整候選方案內一起評分，商品名稱的重複與候選描述容易影響操作選擇；最終分數又混合 rerank 0.65 與 LCS 字元相似度 0.35。
新版將「操作選擇」和「商品／指標參數選擇」分開，各自留下分數、分差、候選及停止原因。

操作階段
- 先依既有名稱與同義詞辨認對象，以最長且不重疊的文字保留商品、分類或指標；同一文字對應不同分類欄位時保留歧義。
- 操作查詢遮罩商品名稱，但保留類型，例如「商品」「符合分類條件的商品」「AUM 指標」「收入指標」，降低名稱重複對操作評分的干擾。
- 五種操作各有同等數量的用途描述；用既有 Cohere reranker 比較，按操作分組取最高分，再檢查與其他操作／能力文件的分差。
- 加入實際數值、多項分析、排除條件等能力範圍文件，只供停止與診斷，沒有新增第六種可執行操作。
- 能力文件並不可靠地驗證完整需求。第 18 題就是反例；有些不支援的題目也只是因低分停止，不能說已正確理解其所有需求。

參數階段
- 只比較選中操作內的商品／分類／指標候選，不再讓不同操作的完整長方案混在一起競爭。
- 保留明確辨認的商品、分類條件、指標及 AUM／收入領域；商品說明題不再無條件套用預設 AUM。
- 參數文件保留業務名稱與同義詞；分類欄位名稱另列，避免「信託」等相同文字掩蓋不同欄位。
- 比例候選明列分子、分母及方向；目前 reranker 仍未穩定分開正反方向。
- 檢查方案是否涵蓋已辨認的對象；不能完整保留時停止。但目前這項檢查只涵蓋已辨認的商品／分類／指標，並不涵蓋日期、客戶門檻與持有關聯。
- 最終決策移除 LCS 字元加權，使用兩段各自的 rerank 分數。
- minScore=0.25、minMargin=0.06 數值未調低。只有一個完整參數候選時檢查最低分數，不虛構第二名分差；因此不可把整體決策邏輯說成完全沒變。

保持不變
- 五種執行操作：ratio、list、membership、composition、explain。
- 商品解析、父子去重、關係類型限制、DFS、循環檢查、到達指定目標指標即停止等走圖執行內容。
- 概念與映射 Cypher、合併子圖程式、回答 prompt／模型、原有憑證引用。
- 模型：embedding=qwen/qwen3-embedding-4b；rerank=cohere/rerank-v3.5；回答=openai/gpt-5.6-luna。
- 本輪 Aura 僅讀取，未新增圖節點、property 或關係；沒有執行 Oracle／底表餘額查詢。

程式核對注意
selection_v4/selection.cjs 是新增的檢索決策程式；build.py 從 subgraph_v3/router.cjs 抽取原圖運算與五種操作產生新版 router.cjs。
test_selection.cjs 與 invariants.json 核對走圖／操作內容保留原文。新檔仍含 legacy* 函數及舊相似度函數，不能只因搜尋到 LCS 就判定新版最後決策仍在使用；應看新 execute → decideParameters 的實際呼叫。
合成向量與分數測試只驗證程式契約，不代表真實語意檢索的準確率。

以下只操作本機既有證據／檢查程式，不會自行部署或執行雲端題目；本次文件更新沒有再執行它們：
node deliverables/single_turn_qa/rag_v1/selection_v4/test_selection.cjs
python -X utf8 deliverables/single_turn_qa/rag_v1/selection_v4/inspect_results.py
python -X utf8 deliverables/single_turn_qa/rag_v1/selection_v4/report.py
python -X utf8 deliverables/single_turn_qa/rag_v1/selection_v4/verify_saved.py
其中 inspect_results.py、report.py、verify_saved.py 會重建本機衍生報告／核對檔；它們不是新的雲端重測。
workflow.regression.json 只是暫時測試用。若未來再測，完成後必須恢復 workflow.updated.json 的正常單題入口，再以新的雲端原生匯出核對。
