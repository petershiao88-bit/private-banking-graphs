二、改動
新增 Integrate Dialogue、Integration Chat Model、Apply Dialogue Integration 三節點。
資料流：Prepare Jev Request 完整圖驗證 → Integrate Dialogue → Apply Dialogue Integration → Jev API → Process Jev Decision → 原映射／回答流程。
整合模型沿用 QA Chat Model 相同 OpenRouter 模型 openai/gpt-5.6-luna 與既有 credential；主要回答與 Jev 模型／採樣設定不變。
整合輸出為 standaloneQuestion、逐組 requests（subject/productCode/domain/sourceTurns）、unresolved；逐組保留配對，不把產品集合×指標集合展開。
未指定指標可為 null，對象有歧義可 productCode=null 並保留 unresolved；原始問題與 history 不被改寫覆蓋。每輪從原始問答重算，整合結果不存記憶。
Apply 節點檢查 JSON schema、產品代碼／指標合法性與來源輪次範圍；格式錯明確失敗，沒有默默回退或額外模型修復。
Prepare Jev Request 加入 currentRequest 的逐組配對指令；原 39 條路徑及完整圖驗證仍在。
Process 只選 choice===included；uncertain 留在 decisions／uncertainPathsNotQueried，不送映射。候選子圖與完整概念圖仍分開。
Answer Question 另收到整合提示，原始問答仍為需求依據；原 system prompt 與來源忠實規則保留。
原 18 節點身份與位置、Aura 查詢、來源 SQL、既有模型、settings 保留。另一個單輪工作流程 Td4cymdWpu8sYNkv 不屬本輪，未修改。
