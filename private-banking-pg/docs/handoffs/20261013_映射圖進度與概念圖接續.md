## 已確定的建模方向

- 概念間關係需要清楚說明業務定義、納入方式及限制。分類與衡量對象關係可用簡短定義；彙總關係另保留必要規則。
- 關係不必保存整段原始 SQL；以可回溯來源的計算規則取代，保留會改變結果的篩選與處理邊界。
- 父項包含子項，不能把父項與子項再相加。資料層級、版本、母體、日期與分組粒度必須一致。
- AUM 是快照；目前各分類最新可用日期仍屬草稿查詢規則，不是每客戶各自取最新日，也不能跨日／跨月直接加總。
- 收入是期間流量；客戶明細與組織報表的範圍不同，不能混成相同母體。
- AO 目前按月份與客戶對應。SQL 角色範圍包括 CA 及指定 VP 職務，不能據此認定所有 AO 都是私銀理專或具特定資格。

- 規劃型信託與信託保管已標示 `classification_only`／`requires_source_level_split`；修正知識表達不代表來源資料已增加可拆分欄位。

- AUM 主版與另版、收入明細與報表的母體／日期差異仍需分開使用。

- JSON 中 `calculationRules`／`queryRules` 仍保留資料庫的 JSON 字串型態；使用時要解析對應 property。
